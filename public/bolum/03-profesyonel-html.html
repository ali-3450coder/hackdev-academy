▸01 HTML Yazım Standartları ve Code Style

HTML Yazım Kuralları
<!-- ✅ Doğru format -->
<!DOCTYPE html>
<html lang="tr">
<head>
  <meta charset="UTF-8">  <!-- 2 boşluk girintileme -->
  <title>Başlık</title>
</head>
<body>

  <!-- ✅ Küçük harf etiket adları -->
  <h1 class="baslik">Başlık</h1>

  <!-- ✅ Çift tırnak kullan -->
  <img src="foto.jpg" alt="Açıklama">

  <!-- ✅ Boolean özellik kısa form -->
  <input type="checkbox" checked>
  <script defer src="app.js"></script>

  <!-- ❌ Yanlış: büyük harf, tek tırnak, gereksiz kapanış -->
  <IMG SRC='foto.jpg' ALT='Açıklama' />
  <INPUT TYPE='checkbox' CHECKED='checked' />

</body>
</html>
💡 EditorConfig ve Prettier: .editorconfig dosyası ile tüm ekip aynı formatı kullanır. Prettier otomatik format uygular.

▸06 Web Performansı — Critical CSS, Lazy Loading, Preload

Performans Optimizasyon Teknikleri
<head>
  <!-- Kritik CSS inline (ilk görünüm için) -->
  <style>
    /* Yalnızca above-the-fold için kritik stiller */
    body { margin: 0; font-family: sans-serif; }
    header { background: #080c12; }
  </style>

  <!-- Ana CSS lazy (blocking yok) -->
  <link rel="preload" href="style.css" as="style"
    onload="this.onload=null;this.rel='stylesheet'">
  <noscript><link rel="stylesheet" href="style.css"></noscript>

  <!-- Font preload -->
  <link rel="preload" href="font.woff2" as="font" type="font/woff2" crossorigin>

  <!-- DNS prefetch ve preconnect -->
  <link rel="preconnect" href="https://fonts.googleapis.com">
  <link rel="dns-prefetch" href="https://analytics.example.com">
</head>

<body>
  <!-- LCP görseli: fetchpriority="high" -->
  <img src="hero.webp" alt="Hero" fetchpriority="high" width="1200" height="600">

  <!-- Diğer görseller: lazy loading -->
  <img src="foto.webp" alt="Foto" loading="lazy" width="800" height="600">

  <!-- Script defer -->
  <script defer src="app.js"></script>
</body>

▸07 Responsive Design Temelleri

Viewport ve Mobile-First Yaklaşım
<!-- Viewport meta: ZORUNLU -->
<meta name="viewport" content="width=device-width, initial-scale=1.0">

<!-- Responsive görsel -->
<img
  src="foto-800.jpg"
  srcset="foto-400.jpg 400w, foto-800.jpg 800w, foto-1600.jpg 1600w"
  sizes="(max-width: 480px) 400px, (max-width: 900px) 800px, 1600px"
  alt="Responsive fotoğraf"
>

<!-- CSS: Mobile-First -->
<style>
  /* Mobil: temel stiller (varsayılan) */
  .grid { display: block; }

  /* Tablet: 768px ve üstü */
  @media (min-width: 768px) {
    .grid { display: grid; grid-template-columns: 1fr 1fr; }
  }

  /* Desktop: 1200px ve üstü */
  @media (min-width: 1200px) {
    .grid { grid-template-columns: repeat(3, 1fr); }
  }

  /* Koyu tema tercihi */
  @media (prefers-color-scheme: dark) {
    body { background: #080c12; color: #e8edf5; }
  }

  /* Az animasyon tercihi */
  @media (prefers-reduced-motion: reduce) {
    * { animation: none !important; transition: none !important; }
  }
</style>

▸09 Form UX Best Practices

Kullanıcı Dostu Form Tasarımı
<form autocomplete="on">
  <!-- autocomplete değerleri -->
  <input name="name" autocomplete="name" type="text">
  <input name="email" autocomplete="email" type="email">
  <input name="tel" autocomplete="tel" type="tel" inputmode="tel">
  <input name="current-password" autocomplete="current-password" type="password">
  <input name="new-password" autocomplete="new-password" type="password">
  <input name="street-address" autocomplete="street-address">
  <input name="postal-code" autocomplete="postal-code" inputmode="numeric">
  <input name="cc-number" autocomplete="cc-number" inputmode="numeric">

  <!-- inputmode: doğru klavye aç -->
  <input inputmode="numeric">   → Numpad
  <input inputmode="email">     → @ tuşu görünür
  <input inputmode="url">       → . ve / tuşu kolay
  <input inputmode="search">    → "Enter" yerine "Ara"
  <input inputmode="decimal">   → Ondalık numpad

  <!-- autofocus: sadece bir elemana -->
  <input type="text" autofocus>

  <!-- enterkeyhint: mobil klavye Enter butonu -->
  <input enterkeyhint="next">      → "Sonraki"
  <input enterkeyhint="done">      → "Bitti"
  <input enterkeyhint="search">    → "Ara"
  <input enterkeyhint="send">      → "Gönder"
</form>

▸10 HTML ve Güvenlik — CSP Gerçek Uygulama

🛡️ Content Security Policy (CSP)

CSP, XSS saldırılarını önleyen en güçlü güvenlik başlığıdır. Hangi kaynaklardan içerik yüklenebileceğini belirler.

CSP Uygulama Yöntemleri
<!-- Yöntem 1: Meta etiketi (sınırlı) -->
<meta http-equiv="Content-Security-Policy"
  content="
    default-src 'self';
    script-src 'self' 'nonce-abc123';
    style-src 'self' 'unsafe-inline' https://fonts.googleapis.com;
    font-src 'self' https://fonts.gstatic.com;
    img-src 'self' https: data:;
    connect-src 'self' https://api.example.com;
    frame-ancestors 'none';
    base-uri 'self';
    form-action 'self'
  "
>

<!-- Yöntem 2: HTTP Header (tercih edilen) -->
<!-- Sunucuda: Content-Security-Policy: ... -->

<!-- Nonce ile inline script -->
<script nonce="abc123">
  // Bu script güvenilir
</script>

<!-- Diğer güvenlik başlıkları -->
<!-- X-Frame-Options: DENY              → Clickjacking önle -->
<!-- X-Content-Type-Options: nosniff   → MIME sniffing önle -->
<!-- Referrer-Policy: strict-origin    → Referrer kontrolü -->
<!-- Permissions-Policy: camera=()     → API erişimini kısıtla -->

▸16 Print CSS — Baskı için Stil

Print Media Query
<link rel="stylesheet" href="print.css" media="print">

<style>
  @media print {
    /* Gereksiz elemanları gizle */
    nav, aside, .sidebar, .topbar,
    button, .no-print { display: none !important; }

    /* Link URL'lerini göster */
    a[href^="http"]::after {
      content: " (" attr(href) ")";
      font-size: 0.8em;
      color: #555;
    }

    /* Sayfa sonu kontrolü */
    h2, h3 { page-break-after: avoid; }
    img, table, figure { page-break-inside: avoid; }

    /* Sayfa kenar boşlukları */
    @page {
      margin: 2cm;
      size: A4 portrait;
    }

    /* Renkleri baskıya uygun yap */
    body { color: #000 !important; background: #fff !important; }
    * { box-shadow: none !important; text-shadow: none !important; }
  }
</style>

▸21 Pratik Görevler

Bu bölümde öğrendiklerini pekiştirmek için aşağıdaki görevleri tamamla:

📝 Bölüm 3 Quizi

12 soru · %70 geçme eşiği · Bölümü tamamlamak için gerekli

1. Content Security Policy (CSP) ne işe yarar?
a) Şifreleme sağlar
b) Hangi kaynaklardan içerik yüklenebileceğini belirleyerek XSS önler
c) Veritabanı bağlantısı güvenliğini sağlar
d) CDN performansını artırır
✓ B — CSP, tarayıcıya hangi kaynakların güvenilir olduğunu söyler. Saldırganın enjekte ettiği scriptler politikaya uymadığı için çalışmaz.
2. Email HTML'de neden table tabanlı layout kullanılır?
a) CSS daha hızlı yüklenir
b) Tablo layoutu daha güzel görünür
c) Email istemcileri modern CSS'i tam desteklemez, tablo evrensel çalışır
d) SEO için gereklidir
✓ C — Outlook gibi istemciler Flexbox/Grid'i desteklemez. Table layout 20 yıldır tutarlı çalıştığı için email standardı haline geldi.
3. link rel="preload" ne için kullanılır?
a) Tarayıcıya kritik kaynağı erken yüklemesini söyler, performansı artırır
b) Kaynağı önbelleğe kaydeder
c) SEO için sayfa önceliğini belirler
d) CSS animasyonu başlatır
✓ A — preload, tarayıcıya "bu kaynağı en yüksek öncelikle indir" der. LCP görseli, kritik fontlar ve CSS için idealdir.
4. WCAG 2.1 AA standardında minimum renk kontrastı oranı nedir?
a) 2:1
b) 3:1
c) 4:1
d) 4.5:1
✓ D — WCAG 2.1 AA seviyesinde metin için minimum 4.5:1 kontras oranı gereklidir. Büyük metin (18pt+) için 3:1 yeterlidir.
5. favicon.svg kullanmanın PNG'ye göre avantajı nedir?
a) Daha küçük dosya boyutu her zaman
b) Her çözünürlükte keskin görünür, dark/light tema media query destekler
c) Tüm tarayıcılar SVG favicon'u destekler
d) Animasyon eklenebilir
✓ B — SVG vektörel olduğundan her boyuta net skalenir. Ayrıca @media (prefers-color-scheme: dark) ile tema geçişi yapılabilir.
6. Schema.org JSON-LD hangi amaca hizmet eder?
a) JavaScript kütüphanesi yükler
b) Animasyon verisi sağlar
c) Arama motorlarının içeriği anlamsal olarak anlamasını sağlar (rich snippet)
d) CSS değişkenleri tanımlar
✓ C — JSON-LD, Google'a içeriğin türünü (makale, ürün, kişi) makine-okunabilir formatta anlatır. Bu rich snippet (yıldız, fiyat, breadcrumb) oluşturur.
7. Mobile-first CSS yaklaşımının anlamı nedir?
a) Temel stiller mobil için yazılır, büyük ekranlar min-width media query ile eklenir
b) Mobil cihazlar için ayrı HTML dosyası yazılır
c) JavaScript ile ekran boyutu tespit edilir
d) max-width media query ile mobil için özel stiller yazılır
✓ A — Mobile-first: CSS en küçük ekran için temel yazılır, @media (min-width: 768px) gibi min-width ile büyük ekranlar eklenir. Performans ve önceliklendirme açısından daha verimlidir.
8. Skip link ne için kullanılır?
a) Sayfayı önceki URLye yönlendirir
b) Klavye kullanıcılarının tekrarlanan nav içeriğini atlayıp ana içeriğe geçmesini sağlar
c) Yavaş internet bağlantısında görselleri atlar
d) JavaScript yüklenmeden sayfayı geçerli kılar
✓ B — Tab tuşu ile gezinen kullanıcılar her sayfada nav linklerini tek tek geçmek zorunda kalır. Skip link, ana içeriğe hızlı erişim sağlar.
9. @media print'te a[href^="http"]::after { content: attr(href) } ne sağlar?
a) Linki tıklanabilir yapar
b) SEO için link metnini kopyalar
c) CSS animasyonu başlatır
d) Yazdırılan belgede link URL'lerini metin olarak gösterir
✓ D — Kağıda yazdırıldığında kullanıcı linki tıklayamaz. Bu CSS tekniği, link URL'ini parantez içinde metnin yanına ekler.
10. Lighthouse'un ölçtüğü kategoriler hangileridir?
a) Performance, Accessibility, Best Practices, SEO, PWA
b) Speed, Design, Code Quality, Security
c) HTML, CSS, JavaScript, Fonts
d) Mobile, Desktop, Tablet, Print
✓ A — Google Lighthouse 5 kategori ölçer: Performance (Core Web Vitals), Accessibility, Best Practices, SEO ve PWA.
11. HTML boilerplate'de link rel="canonical" ne için eklenir?
a) CSS stillerini bağlamak için
b) Sayfa başlığını belirlemek için
c) Duplicate content sorununu önlemek için tercih edilen URL'yi belirtir
d) Favicon dosyasını bağlamak için
✓ C — Aynı içerik farklı URL'lerde erişilebilirse (http vs https, www vs non-www), canonical Google'a "bu asıl URL" der ve SEO cezasını önler.
12. PWA'da service worker'ın temel görevi nedir?
a) Form doğrulaması yapmak
b) Ağ isteklerini önbelleğe alarak offline çalışma ve hız sağlamak
c) Kullanıcı verilerini şifrelemek
d) DOM manipülasyonu yapmak
✓ B — Service Worker, tarayıcı ile ağ arasında bir proxy gibi çalışır. Kaynakları cache'ler, böylece internet olmadan da uygulama çalışabilir.
